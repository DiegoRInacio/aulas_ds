Ética em Dados e LGPD

O que é Ética em Dados?

Conceito

"Com grandes volumes de dados vêm grandes responsabilidades."

Adaptado de Tim Berners-Lee, criador da World Wide Web
🔏

Privacidade

Cada pessoa tem o direito de controlar como suas informações pessoais são coletadas, usadas e compartilhadas.

⚖️

Equidade (Fairness)

Algoritmos não devem discriminar grupos de pessoas com base em raça, gênero, origem ou outras características protegidas.

🔍

Transparência

Pessoas afetadas por decisões algorítmicas têm o direito de saber como e por quê essas decisões foram tomadas.

Os três pilares

Qualidade: dado certo, no momento certo — sem isso, todo o resto falha.  |  Governança: políticas claras sobre quem pode acessar, modificar e usar os dados.  |  Ética: garantir que o uso dos dados não cause dano a indivíduos ou grupos.

O que esses casos têm em comum?

Em todos, o problema não estava no algoritmo em si — estava nos dados de treino tendenciosos e na ausência de validação ética antes da implantação. O modelo amplificou desigualdades já existentes na sociedade.

LGPD — Lei Geral de Proteção de Dados

Lei 13.709/2018

O que é?

A LGPD é a lei brasileira que regula o tratamento de dados pessoais — tanto por empresas privadas quanto pelo poder público. Inspirada no GDPR europeu, entrou em vigor em 2020.

Dados pessoais vs dados sensíveis

TipoExemplosProteção
Pessoalnome, e-mail, CPF, endereçoPadrão
Sensívelraça, saúde, biometria, religião, opinião políticaReforçada
Anonimizadodado sem identificação possívelFora da lei
Multa: até 2% do faturamento
Limitada a R$ 50 milhões por infração. A ANPD é o órgão fiscalizador.

As 10 Bases Legais para tratamento

Só é permitido tratar dados pessoais com uma base legal válida:

  • Consentimento
  • Contrato
  • Obrigação legal
  • Políticas públicas
  • Pesquisa
  • Interesse legítimo
  • Proteção do crédito
  • Tutela da saúde
  • Exercício de direitos
  • Proteção da vida

Princípios fundamentais (Art. 6º)

  • Finalidade: propósitos legítimos, explícitos e informados
  • Necessidade: mínimo necessário para a finalidade
  • Transparência: informações claras ao titular
  • Segurança: proteção contra acesso não autorizado
  • Não discriminação: proibição de uso para fins discriminatórios

Direitos do Titular de Dados

LGPD Art. 18
👁️

Acesso

Saber quais dados são mantidos sobre si e como são usados.

✏️

Correção

Solicitar a correção de dados incompletos, inexatos ou desatualizados.

🗑️

Eliminação

Pedir a exclusão dos dados quando o tratamento não for mais necessário.

📦

Portabilidade

Receber os dados em formato estruturado para transferir a outro serviço.

Outros direitos

  • Revogação do consentimento a qualquer momento
  • Informação sobre compartilhamento com terceiros
  • Revisão de decisões automatizadas que afetam o titular
  • Oposição ao tratamento em caso de descumprimento

Na prática: o que sua empresa precisa

  • Canal para receber pedidos dos titulares
  • Prazo de resposta definido (ANPD pode regulamentar)
  • DPO — Data Protection Officer (encarregado)
  • Inventário de dados pessoais tratados
  • RIPD para processos de alto risco

Regra prática

Um dado pode ser completo (sem nulos), consistente (formato correto) e ainda assim errado (inexato). As 6 dimensões são independentes — precisamos verificar todas.

Diagnóstico de Qualidade — Prática

Hands-on
import pandas as pd
import numpy as np

df = pd.DataFrame({
    'cpf':   ['123.456.789-00','987.654.321-00',
               '111.222.333-44','123.456.789-00',
               None, '000.000.000-00'],
    'nome':  ['Ana Silva','Bruno Lima','Carla',
               'Ana Silva','Diego','Empresa XYZ'],
    'idade': [28, 35, -5, 28, 999, 42],
    'email': ['ana@email.com','bruno@','carla@email.com',
               'ana@email.com','diego@email.com', None],
    'renda': [3500, None, 4200, 3500, 8900, None]
})

N = len(df)
print("=" * 55)
print("   RELATÓRIO DE QUALIDADE DE DADOS")
print("=" * 55)

# 1. Completude
print("\n[1] COMPLETUDE:")
for col in df.columns:
    nulos = df[col].isnull().sum()
    pct = nulos / N * 100
    status = "OK" if nulos == 0 else f"ATENÇÃO: {nulos} nulos ({pct:.0f}%)"
    print(f"   {col:<10} {status}")

# 2. Unicidade
dups = df['cpf'].duplicated(keep=False).sum()
print(f"\n[2] UNICIDADE — CPFs duplicados: {dups} registros")

# 3. Validade — idades fora de [0, 120]
invalidas = df[(df['idade'] < 0) | (df['idade'] > 120)]
print(f"\n[3] VALIDADE — Idades inválidas: "
      f"{len(invalidas)} → {invalidas['idade'].tolist()}")

# 4. Validade — e-mails malformados
emails_ruins = df[~df['email'].fillna('')
                  .str.contains(r'^\S+@\S+\.\S+$')]
print(f"             Emails inválidos: {len(emails_ruins)}")

# Score estimado
problemas = (dups + len(invalidas) +
             len(emails_ruins) +
             df.isnull().sum().sum())
score = max(0, 100 - problemas * 8)
print(f"\n[SCORE GERAL]: {score:.0f}/100")
print("=" * 55)

Anonimização — Protegendo Dados Pessoais

LGPD na Prática

Dado anonimizado está fora do escopo da LGPD — mas anonimização real é difícil. A maioria dos métodos produz pseudonimização, que ainda é dado pessoal.

TécnicaComo funcionaReversível?
MascaramentoAna Silva → *** *****Não
PseudonimizaçãoAna Silva → USR_001Sim (com tabela)
Generalização28 anos → 20-30 anosParcialmente
SupressãoRemove o campoNão
HashingCPF → SHA-256(...)Não
Ruído DiferencialAdiciona ruído estatísticoNão

Risco de Reidentificação

Em 2006, a Netflix divulgou 100 milhões de avaliações "anonimizadas". Pesquisadores da Universidade do Texas reidentificaram usuários cruzando com avaliações públicas do IMDb.


Dados aparentemente anonimizados podem ser reidentificados quando combinados com outras fontes. Quanto mais campos, maior o risco.

k-Anonimato

Um conjunto é k-anônimo se cada registro é indistinguível de pelo menos k-1 outros. Quanto maior o k, menor o risco de reidentificação — mas maior a perda de utilidade dos dados.

Anonimização — Prática

Hands-on
import pandas as pd
import hashlib

# Dados pessoais originais
df_orig = pd.DataFrame({
    'nome':   ['Ana Silva','Bruno Lima',
               'Carla Souza','Diego Ramos'],
    'cpf':    ['123.456.789-00','987.654.321-00',
               '111.222.333-44','444.555.666-77'],
    'email':  ['ana@mail.com','bruno@mail.com',
               'carla@mail.com','diego@mail.com'],
    'idade':  [28, 35, 22, 41],
    'renda':  [3500, 8000, 4200, 6100],
    'cidade': ['Rio de Janeiro','São Paulo',
               'Belo Horizonte','Curitiba']
})

print("ANTES — DADO PESSOAL (uso restrito):")
print(df_orig.to_string())

df_anon = df_orig.copy()

# 1. Pseudonimização: nome e e-mail → ID
df_anon['user_id'] = ['USR_' + str(i+1).zfill(3)
                       for i in range(len(df_anon))]
df_anon = df_anon.drop(columns=['nome','email'])

# 2. Hashing do CPF (irreversível)
df_anon['cpf_hash'] = df_anon['cpf'].apply(
    lambda x: hashlib.sha256(x.encode()).hexdigest()[:16]
)
df_anon = df_anon.drop(columns=['cpf'])

# 3. Generalização da idade
bins   = [0, 20, 30, 40, 50, 100]
labels = ['<20','20-30','30-40','40-50','50+']
df_anon['faixa_etaria'] = pd.cut(
    df_anon['idade'], bins=bins, labels=labels
)
df_anon = df_anon.drop(columns=['idade'])

# 4. Supressão da cidade (reidentificação alta)
df_anon = df_anon.drop(columns=['cidade'])

print("\nDEPOIS — DADO ANONIMIZADO (pode compartilhar):")
print(df_anon.to_string())

O que foi feito

  • Pseudonimização: nome e e-mail substituídos por ID sequencial — ainda é dado pessoal, mas protege a identidade direta
  • Hashing: CPF transformado em SHA-256 — irreversível sem tabela de lookup
  • Generalização: idade exata → faixa etária — perde precisão, ganha privacidade
  • Supressão: cidade removida — combinada com outros campos poderia identificar

Boas práticas

  • Sempre adicione salt ao hash (evita rainbow tables)
  • Avalie o risco de reidentificação antes de publicar
  • Mantenha a tabela de pseudonimização em ambiente separado e seguro
  • Revise as técnicas quando o dataset for combinado com outros

Viés nos Dados — O Problema Invisível

Fairness

Viés (bias) em dados ocorre quando o conjunto de dados não representa adequadamente a realidade, levando modelos a tomar decisões injustas.

Tipos de viés

TipoDescrição
Viés de seleçãoAmostra não representa a população
Viés históricoDados refletem discriminações do passado
Viés de confirmaçãoBusca dados que confirmam a hipótese
Viés de mediçãoO instrumento de coleta favorece um grupo
Viés de agregaçãoUm modelo para todos grupos distintos

Como o viés se propaga

1. Dados históricos refletem desigualdades da sociedade
2. Modelo aprende esses padrões
3. Modelo amplifica a desigualdade nas predições
4. Decisões automatizadas perpetuam a discriminação
5. Feedback retroalimenta novos dados com o mesmo viés


→ Isso se chama feedback loop discriminatório

Métricas de fairness

  • Paridade demográfica: taxa de aprovação igual entre grupos
  • Igualdade de oportunidade: recall igual entre grupos
  • Calibração: confiança do modelo precisa ser igual entre grupos

Detecção de Viés — Prática

Hands-on
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

np.random.seed(7)

# Viés de representação: Grupo A muito mais amostrado
n_a, n_b = 180, 20  # 9:1 — desbalanceado!

g_a = pd.DataFrame({
    'grupo':    ['A'] * n_a,
    'score':    np.random.normal(72, 10, n_a).clip(0,100),
    'aprovado': np.random.choice([0,1], n_a, p=[.35,.65])
})
g_b = pd.DataFrame({
    'grupo':    ['B'] * n_b,
    'score':    np.random.normal(70, 10, n_b).clip(0,100),
    'aprovado': np.random.choice([0,1], n_b, p=[.45,.55])
})
df = pd.concat([g_a, g_b], ignore_index=True)

# --- Análise de viés ---
print("=== Representatividade ===")
rep = df['grupo'].value_counts(normalize=True).mul(100)
print(rep.to_frame('proporção (%)').round(1))

print("\n=== Taxas por grupo ===")
analise = df.groupby('grupo').agg(
    n=('aprovado','count'),
    score_medio=('score','mean'),
    taxa_aprovacao=('aprovado','mean')
).round(2)
print(analise)

# --- Visualização ---
fig, axes = plt.subplots(1, 2, figsize=(12, 4))

# Desbalanceamento
contagens = df['grupo'].value_counts()
axes[0].bar(contagens.index, contagens.values,
            color=['#3498db','#e11d48'], width=.5)
axes[0].set_title('Viés de Representação\n'
                   '(Grupo B sub-representado!)')
axes[0].set_ylabel('N° amostras')

# Distribuição de scores
for g, cor in [('A','#3498db'),('B','#e11d48')]:
    axes[1].hist(df[df['grupo']==g]['score'],
                 alpha=.6, bins=15, color=cor,
                 label=f'Grupo {g}')
axes[1].set_title('Scores similares,\namostras muito desiguais')
axes[1].legend()

plt.tight_layout()
plt.show()

O que o código mostra

Grupos A e B têm desempenho estatisticamente similar (score ≈ 70–72), mas o Grupo B tem apenas 20 amostras contra 180 do Grupo A. Um modelo treinado assim será muito menos preciso para o Grupo B — que pode ser exatamente o grupo já marginalizado.

Como mitigar o viés

  • Oversampling: duplicar amostras do grupo minoritário (SMOTE)
  • Undersampling: reduzir amostras do grupo majoritário
  • Pesos de classe: class_weight='balanced' no sklearn
  • Coletar mais dados para grupos sub-representados
  • Avaliar métricas por grupo separadamente
Disparidade = taxa_A / taxa_B
Regra dos 80%: se disparidade < 0,8 ou > 1,25, há problema de fairness (EEOC Guideline)

Governança de Dados

Framework

Governança de dados é o conjunto de políticas, processos e responsabilidades que garantem que os dados são gerenciados de forma adequada em toda a organização.

Papéis e responsabilidades

PapelResponsabilidade
Data OwnerResponsável pelo domínio de negócio dos dados
Data StewardGarante qualidade e conformidade diária
Data EngineerPipelines, armazenamento e acesso técnico
DPOConformidade com LGPD e privacidade
Data ScientistUso ético e justo dos dados em modelos

Pilares de um bom programa de governança

  1. Catálogo de dados: inventário de todos os conjuntos de dados, seus donos e classificação de sensibilidade
  2. Políticas de acesso: quem pode ver, editar ou excluir cada tipo de dado
  3. Linhagem de dados: rastrear de onde os dados vieram e como foram transformados
  4. Monitoramento de qualidade: alertas automáticos para degradação de qualidade
  5. Gestão do ciclo de vida: quando os dados devem ser arquivados ou excluídos

Privacidade e LGPD

  • [ ] Valores ausentes foram tratados com justificativa?
  • [ ] Outliers foram investigados, não apenas removidos?
  • [ ] Os dados de treino e teste são representativos?
  • [ ] Há duplicatas ou inconsistências não tratadas?

Fairness / Equidade

  • [ ] Performance foi avaliada por grupos sensíveis?
  • [ ] O dataset não é desbalanceado entre grupos?
  • [ ] O modelo foi testado contra usos discriminatórios?
  • [ ] A disparidade de taxa de aprovação está abaixo de 25%?

Transparência e Accountability

  • [ ] O modelo pode ser explicado para não-técnicos?
  • [ ] As limitações e incertezas estão documentadas?
  • [ ] Há processo para contestar decisões automáticas?
  • [ ] O responsável pelo modelo está identificado?
