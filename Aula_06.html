Visualização de Dados e Storytelling Analítico

Por que visualizar dados?

Conceito

"Um gráfico bem feito comunica em segundos o que uma tabela leva minutos para transmitir."

Edward Tufte — The Visual Display of Quantitative Information
🧠

Cognição

O cérebro humano processa imagens 60.000x mais rápido que texto. Visualizações exploram esse canal de forma eficiente.

🔍

Exploração

Gráficos revelam padrões, outliers e tendências que passam despercebidos em tabelas com milhares de linhas.

📣

Comunicação

Apresentar resultados a stakeholders que não são técnicos requer clareza visual, não fórmulas nem código.

Exemplo clássico: Quarteto de Anscombe

Quatro conjuntos de dados com média, variância e correlação idênticas — mas gráficos completamente diferentes. Só visualizando você vê a diferença.

Princípios de Boas Visualizações

Teoria
  1. Clareza antes de beleza — o leitor precisa entender sem esforço. Remova elementos decorativos que não informam.
  2. Escolha o gráfico certo — cada tipo de gráfico tem um propósito. Usar o errado distorce a mensagem.
  3. Comece o eixo Y em zero (para barras) — truncar o eixo exagera diferenças e engana o leitor.
  4. Use cores com intenção — não use 12 cores só porque ficam bonitas. Cada cor deve ter significado.
  5. Título e rótulos obrigatórios — um gráfico sem título é um mistério. Sempre informe o que está sendo mostrado.
  6. Menos é mais (Data-ink ratio) — princípio de Tufte: maximize a proporção de tinta que representa dados.

Erros mais comuns

  • Pie charts com muitas fatias (use barras)
  • 3D desnecessário que distorce proporções
  • Eixo Y que não começa em zero em barras
  • Cores inacessíveis para daltônicos
  • Sobrecarga de informação em um único gráfico
  • Ausência de fonte dos dados
Data-ink ratio = Tinta de dados / Tinta total
Maximize esse valor. Cada elemento visual deve justificar sua existência.

Qual gráfico usar?

Referência
ObjetivoGráfico indicadoQuando evitar
Comparar categoriasBarras (bar chart)Muitas categorias (> 10)
Evolução no tempoLinha (line chart)Dados sem continuidade temporal
Distribuição de valoresHistograma / boxplotQuando não há dados suficientes
Relação entre 2 variáveisDispersão (scatter)Variáveis categóricas
Proporção de partesBarras empilhadasEvite pie chart com mais de 3 fatias
Correlação entre variáveisHeatmapPoucas variáveis (use scatter)
Comparar distribuiçõesBoxplot / violinplotQuando outliers não importam

Dica prática

Antes de codar, pergunte: "O que eu quero que o leitor conclua com esse gráfico?" A resposta define o tipo e o design.

Matplotlib — O Essencial

Prática
import matplotlib.pyplot as plt
import numpy as np

# Dados de vendas por trimestre
trimestres = ['Q1', 'Q2', 'Q3', 'Q4']
vendas_2024 = [120, 145, 162, 198]
vendas_2023 = [100, 130, 140, 175]

fig, ax = plt.subplots(figsize=(8, 5))

x = np.arange(len(trimestres))
largura = 0.35

ax.bar(x - largura/2, vendas_2023, largura,
       label='2023', color='#0d9488', alpha=0.8)
ax.bar(x + largura/2, vendas_2024, largura,
       label='2024', color='#e05c2a', alpha=0.8)

ax.set_title('Vendas por Trimestre (mil R$)')
ax.set_xlabel('Trimestre')
ax.set_ylabel('Vendas (R$ mil)')
ax.set_xticks(x)
ax.set_xticklabels(trimestres)
ax.legend()
ax.spines[['top','right']].set_visible(False)

plt.tight_layout()
plt.show()

Anatomia de uma figura Matplotlib

  • Figure: a tela inteira (pode ter vários gráficos)
  • Axes: um gráfico dentro da figure
  • Axis: os eixos X e Y
  • Artist: qualquer elemento visual (barra, linha, texto...)

Boas práticas no código

  • Use fig, ax = plt.subplots() (estilo orientado a objeto)
  • Defina figsize para controlar proporções
  • Remova bordas desnecessárias com spines
  • Use tight_layout() para evitar cortes

Seaborn — Visualizações Estatísticas

Prática
import seaborn as sns
import pandas as pd
import matplotlib.pyplot as plt

# Dataset de exemplo (built-in do Seaborn)
df = sns.load_dataset('tips')
# colunas: total_bill, tip, sex, smoker, day, time, size

# --- Histograma com KDE ---
fig, axes = plt.subplots(1, 2, figsize=(12, 4))

sns.histplot(df['total_bill'], kde=True,
             color='#0d9488', ax=axes[0])
axes[0].set_title('Distribuição das Contas')

# --- Scatter com regressão ---
sns.regplot(x='total_bill', y='tip',
            data=df, color='#e05c2a', ax=axes[1])
axes[1].set_title('Conta vs Gorjeta')

plt.tight_layout()
plt.show()

# --- Heatmap de correlação ---
numeric = df.select_dtypes(include='number')
sns.heatmap(numeric.corr(), annot=True,
            cmap='coolwarm', center=0)
plt.title('Correlações')
plt.show()

Por que Seaborn?

  • API de alto nível sobre Matplotlib
  • Integra diretamente com DataFrames Pandas
  • Gráficos estatísticos prontos (boxplot, violinplot, pairplot)
  • Paletas de cores acessíveis por padrão

Gráficos mais usados

  • sns.barplot — média com IC
  • sns.boxplot — distribuição por grupo
  • sns.heatmap — correlações
  • sns.pairplot — explorar todas as relações
  • sns.scatterplot — com agrupamentos por cor

Exploração Visual Completa

Prática
import seaborn as sns
import matplotlib.pyplot as plt

df = sns.load_dataset('tips')

# Pairplot — todas as relações de uma vez
sns.pairplot(df, hue='sex',
             palette={'Male':'#0d9488','Female':'#e05c2a'})
plt.suptitle('Exploração Geral — Tips Dataset',
             y=1.02)
plt.show()

# Boxplot por categoria
fig, ax = plt.subplots(figsize=(8, 5))
sns.boxplot(x='day', y='total_bill',
            hue='sex', data=df,
            palette='Set2', ax=ax)
ax.set_title('Conta por Dia e Gênero')
ax.spines[['top','right']].set_visible(False)
plt.tight_layout()
plt.show()

# Violin para ver distribuição completa
sns.violinplot(x='day', y='tip', data=df,
               palette='coolwarm', inner='box')
plt.title('Distribuição das Gorjetas por Dia')
plt.show()

Dica: comece sempre com pairplot

Num novo dataset, sns.pairplot(df) em uma linha já mostra todas as relações entre variáveis numéricas. É o primeiro passo da análise exploratória visual.

Boxplot vs Violinplot

  • Boxplot: mostra mediana, quartis e outliers — mais objetivo
  • Violinplot: mostra a distribuição completa (KDE) — mais informativo, porém mais complexo de ler
  • Para stakeholders técnicos: violinplot. Para executivos: boxplot ou média com barras de erro.

Storytelling Analítico

Conceito

"Os dados informam. A narrativa convence. Os dois juntos transformam decisões."

Cole Nussbaumer Knaflic — Storytelling with Data

A estrutura do Storytelling

  1. Contexto: Quem é o público? Qual decisão está em jogo?
  2. Problema: O que os dados revelam de surpreendente ou preocupante?
  3. Análise: O que causou esse padrão? (correlação, segmentação)
  4. Insight: Qual é a mensagem principal? Uma frase clara.
  5. Ação: O que o público deve fazer com essa informação?

Exemplo real

Ruim: "O gráfico mostra as vendas dos últimos 6 meses por região."

Com storytelling: "As vendas da região Sul caíram 23% em março enquanto o restante do país cresceu. Coincide com a abertura de um concorrente local. Se não agirmos, a perda projetada é de R$ 2M até dezembro."

Ferramentas de apresentação

  • Jupyter Notebook (exploratório)
  • Power BI / Tableau (dashboards)
  • Plotly / Dash (interativo em Python)
  • Streamlit (app web em Python)

Prática — Narrativa com Dados

Hands-on
import pandas as pd
import matplotlib.pyplot as plt
import seaborn as sns

# Simulando dados de e-commerce
dados = {
    'mes': ['Jan','Fev','Mar','Abr','Mai','Jun'],
    'receita': [80, 95, 70, 110, 130, 125],
    'clientes': [400, 450, 380, 520, 600, 570],
    'ticket_medio': [200, 211, 184, 212, 217, 219]
}
df = pd.DataFrame(dados)

fig, axes = plt.subplots(1, 3, figsize=(14, 4))
fig.suptitle('Análise de Performance — 1º Semestre 2024',
             fontsize=14, fontweight='bold')

# Receita por mês
axes[0].bar(df['mes'], df['receita'],
            color=['#e05c2a' if v==70 else '#0d9488'
                   for v in df['receita']])
axes[0].set_title('Receita (R$ mil)')
axes[0].set_ylim(0, 150)
axes[0].annotate('Queda em Março\n(-26%)',
                 xy=('Mar', 70), xytext=('Abr', 60),
                 fontsize=8, color='#e05c2a',
                 arrowprops=dict(arrowstyle='->', color='#e05c2a'))

# Clientes ativos
axes[1].plot(df['mes'], df['clientes'],
             marker='o', color='#0d9488', linewidth=2)
axes[1].set_title('Clientes Ativos')
axes[1].fill_between(range(6), df['clientes'],
                     alpha=0.1, color='#0d9488')

# Ticket médio
axes[2].bar(df['mes'], df['ticket_medio'],
            color='#2563eb', alpha=0.7)
axes[2].set_title('Ticket Médio (R$)')

for ax in axes:
    ax.spines[['top','right']].set_visible(False)

plt.tight_layout()
plt.show()

O que essa narrativa comunica

Março foi um mês atípico em receita (-26%), mas o ticket médio e a base de clientes se recuperaram em abril. Isso sugere um problema pontual de demanda, não estrutural — o negócio voltou ao crescimento em seguida.

Técnicas usadas

  • Cor de destaque para o outlier (Março em vermelho)
  • Anotação direta no gráfico (annotation)
  • Título geral contextualizando o período
  • Três métricas complementares side-by-side
  • Remoção das bordas desnecessárias

Bancos de Dados Não Relacionais (NoSQL)

O que é NoSQL?

Conceito

"NoSQL não significa 'sem SQL'. Significa 'Not Only SQL' — mais opções além do modelo relacional quando ele não se encaixa."

Martin Fowler — NoSQL Distilled

Por que surgiu?

  1. Volume: Google, Amazon e Facebook precisavam armazenar bilhões de registros — escalabilidade horizontal era essencial.
  2. Velocidade: Bancos relacionais com JOINs complexos não sustentavam milhões de requisições por segundo.
  3. Variedade: Dados de redes sociais, IoT e logs não cabem bem em tabelas com esquema fixo.
  4. Flexibilidade: Mudanças de schema em SQL exigem migrações custosas. NoSQL aceita documentos com estruturas diferentes.

Teorema CAP

Um sistema distribuído só pode garantir 2 de 3 propriedades: Consistência, Disponibilidade e Tolerância à partição. NoSQL geralmente prioriza AP ou CP.

As Quatro Famílias de NoSQL

Classificação
📄

Documento

Armazena documentos JSON/BSON. Cada registro pode ter estrutura diferente.

MongoDB, CouchDB, Firestore

Use em: CMS, e-commerce, apps móveis

🔑

Chave-Valor

Estrutura mais simples: uma chave única aponta para um valor qualquer. Ultra-rápido.

Redis, DynamoDB, Memcached

Use em: cache, sessões de usuário, filas

📊

Colunar

Armazena dados por coluna, não por linha. Excelente para analítica em grandes volumes.

Cassandra, HBase, Redshift

Use em: data warehouse, séries temporais

🕸️

Grafo

Dados são nós e arestas. Perfeito para redes de relacionamentos complexos.

Neo4j, Amazon Neptune

Use em: redes sociais, detecção de fraude

FamíliaModelo de dadosLinguagem de consultaPonto forte
DocumentoJSON / BSONMQL (Mongo Query Language)Flexibilidade de schema
Chave-Valorpar chave: valorComandos GET/SET/DELVelocidade extrema
Colunarfamília de colunasCQL (Cassandra)Analítica em massa
Grafonós e arestasCypher (Neo4j)Travessia de relacionamentos

SQL vs NoSQL — Quando usar cada um?

Decisão
CritérioSQLNoSQL
SchemaFixo e validadoFlexível, dinâmico
EscalabilidadeVertical (mais CPU/RAM)Horizontal (mais máquinas)
Transações ACIDNativo e robustoLimitado (Mongo tem desde 4.0)
Consultas complexasJOINs múltiplosDesnormalização necessária
Velocidade de escritaModeradaAlta (sem JOINs na escrita)
ConsistênciaForteEventual (configurável)

Use SQL quando...

  • Dados são bem estruturados e o schema não muda muito
  • Integridade transacional é crítica (financeiro, ERP)
  • Consultas ad-hoc com JOINs complexos são frequentes
  • Time já conhece SQL — menor curva de aprendizado

Use NoSQL quando...

  • Volume é muito alto e precisa escalar horizontalmente
  • Dados são heterogêneos ou mudam frequentemente
  • Latência baixa é crítica (cache, tempo real)
  • Dados têm estrutura de grafo ou hierárquica

CRUD — Create e Read

Prática
from pymongo import MongoClient

client = MongoClient("mongodb://localhost:27017/")
db = client["aula_ds"]
alunos = db["alunos"]

# ---- CREATE ----

# Inserir um documento
resultado = alunos.insert_one({
    "nome": "Ana Souza",
    "curso": "Ciência de Dados",
    "periodo": 3,
    "notas": [8.5, 9.2, 7.8],
    "ativo": True
})
print("ID inserido:", resultado.inserted_id)

# Inserir vários de uma vez
varios = [
    {"nome": "Carlos Lima",  "periodo": 2, "media": 7.1},
    {"nome": "Julia Mendes", "periodo": 3, "media": 9.4},
    {"nome": "Pedro Nunes",  "periodo": 2, "media": 6.8},
]
alunos.insert_many(varios)

# ---- READ ----

# Buscar todos
for doc in alunos.find():
    print(doc)

# Buscar com filtro
alunos_p3 = alunos.find({"periodo": 3})
for doc in alunos_p3:
    print(doc["nome"])

# Buscar apenas alguns campos (projection)
alunos.find({}, {"nome": 1, "media": 1, "_id": 0})

# Condições: maior que
alunos.find({"media": {"$gt": 8.0}})

Operadores de consulta

$gt   → maior que
$gte  → maior ou igual
$lt   → menor que
$lte  → menor ou igual
$ne   → diferente de
$in   → dentro de uma lista
$nin  → fora de uma lista
$and  → condição E
$or   → condição OU

Exemplos de filtros

# média entre 7 e 9
{"media": {"$gte":7, "$lte":9}}

# período 2 ou 3
{"periodo": {"$in": [2, 3]}}

# nome começa com J
{"nome": {"$regex": "^J"}}

CRUD — Update e Delete

Prática
from pymongo import MongoClient

client = MongoClient("mongodb://localhost:27017/")
alunos = client["aula_ds"]["alunos"]

# ---- UPDATE ----

# Atualizar um documento
alunos.update_one(
    {"nome": "Carlos Lima"},          # filtro
    {"$set": {"media": 7.5}}          # operação
)

# Atualizar todos que correspondem ao filtro
alunos.update_many(
    {"periodo": 2},
    {"$inc": {"periodo": 1}}  # incrementa período em 1
)

# Adicionar campo em todos os documentos
alunos.update_many(
    {},
    {"$set": {"turma": "2026-1"}}
)

# ---- DELETE ----

# Deletar um documento
alunos.delete_one({"nome": "Pedro Nunes"})

# Deletar todos com filtro
alunos.delete_many({"ativo": False})

# Deletar TODOS (cuidado!)
# alunos.delete_many({})

# ---- CONTAGEM E LISTAGEM ----
print("Total de alunos:", alunos.count_documents({}))
print("Alunos ativos:",   alunos.count_documents({"ativo": True}))
print("Coleções:", client["aula_ds"].list_collection_names())

Operadores de update

OperadorFunção
$setDefine ou atualiza campo
$unsetRemove um campo
$incIncrementa valor numérico
$pushAdiciona item a um array
$pullRemove item de um array
$renameRenomeia um campo

Atenção: update_one vs update_many

Sempre use o filtro correto. update_many({},...) modifica TODOS os documentos sem confirmação. Teste o filtro com find antes de executar o update.

# EXERCÍCIO: Catálogo de Filmes
# Monte um pequeno banco NoSQL de filmes
# e execute as operações pedidas abaixo.

from pymongo import MongoClient

client = MongoClient("mongodb://localhost:27017/")
filmes_col = client["cinema"]["filmes"]

# --- PASSO 1: Inserir filmes ---
filmes_col.insert_many([
    {"titulo": "Inception",    "ano": 2010, "nota": 8.8,
     "generos": ["Ficção","Thriller"], "diretor": "Nolan"},
    {"titulo": "Parasite",     "ano": 2019, "nota": 8.6,
     "generos": ["Drama","Suspense"],  "diretor": "Bong"},
    {"titulo": "Interstellar", "ano": 2014, "nota": 8.6,
     "generos": ["Ficção","Drama"],    "diretor": "Nolan"},
    {"titulo": "The Godfather","ano": 1972, "nota": 9.2,
     "generos": ["Crime","Drama"],     "diretor": "Coppola"},
    {"titulo": "1917",         "ano": 2019, "nota": 8.3,
     "generos": ["Guerra","Drama"],    "diretor": "Mendes"},
])

# --- PASSO 2: Buscar filmes com nota > 8.5 ---
bons = filmes_col.find({"nota": {"$gt": 8.5}},
                        {"titulo": 1, "nota": 1, "_id": 0})
print("Filmes bem avaliados:")
for f in bons:
    print(f" {f['titulo']} — {f['nota']}")

# --- PASSO 3: Filmes do diretor Nolan ---
nolan = list(filmes_col.find({"diretor": "Nolan"},
                              {"titulo": 1, "ano": 1, "_id": 0}))
print(f"\nFilmes de Nolan ({len(nolan)} encontrados):")
for f in nolan:
    print(f"  {f['titulo']} ({f['ano']})")

# --- PASSO 4: Atualizar nota do Parasite ---
filmes_col.update_one(
    {"titulo": "Parasite"},
    {"$set": {"nota": 8.7, "oscar": True}}
)

# --- PASSO 5: Contar por gênero Drama ---
total_drama = filmes_col.count_documents(
    {"generos": "Drama"}
)
print(f"\nFilmes com gênero Drama: {total_drama}")

Desafio extra

Tente escrever as queries para:

  • Listar filmes ordenados por nota (decrescente)
  • Buscar filmes lançados após 2015
  • Adicionar o campo "assistido: False" em todos
  • Deletar o filme com menor nota

Dica: sort e limit

# Ordenar por nota (desc)
filmes_col.find().sort("nota", -1)

# Top 3 filmes
filmes_col.find().sort(
    "nota", -1).limit(3)

# Após 2015
filmes_col.find(
    {"ano": {"$gt": 2015}})
